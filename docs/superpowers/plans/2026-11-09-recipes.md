# Ricette Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aggiungere a `shared_diet` un ricettario condiviso: ricette (nome, nota, ingredienti con grammatura di default) richiamabili nei pasti, con grammature per persona, espanse in Oggi/sensori/promemoria e sostituite dagli ingredienti nella spesa.

**Architecture:** La logica pura in `model.py` riceve il ricettario come argomento ed espande gli item-ricetta. `store.py` conserva `recipes` accanto a `profiles` (rev per ricetta) e valida i riferimenti. `websocket.py` aggiunge comandi e schemi; la sottoscrizione invia anche `recipes`. Il pannello replica l'espansione in JS, aggiunge la scheda "Ricette" e la riga-ricetta nell'editor.

**Tech Stack:** Python 3.14 / HA 2026.10 (test in Docker `shared-diet-test`), voluptuous, JS vanilla (un file), node:22 per i test JS.

**Spec:** `docs/superpowers/specs/2026-11-09-recipes-design.md` (estende `docs/superpowers/specs/2026-11-09-ha-shared-diet-design.md`)

## Global Constraints

- Item in un pasto: `{food, qty, unit, note}` **oppure** `{recipe: "<recipe_id>"}` (nessun altro campo).
- Ricetta: `{id, name, note, ingredients: [{id, food, qty: float|null, unit}], rev}`; ingredienti sempre semplici; nota ingrediente implicita `""`.
- Profilo: nuovo campo `recipe_qty: {recipe_id: {ingredient_id: float >= 0}}`; assente = `{}`. Solo il numero è personalizzabile, mai l'unità.
- Grammatura effettiva = `profile.recipe_qty[rid][iid]` se presente, altrimenti `ingredient.qty` (anche `None`).
- Testo ricetta (sensori/promemoria): `"Pancake: Farina 60 g, Uova 1 pz"` (ingredienti con `format_item`, separati da `", "`); ricetta inesistente: `"Ricetta mancante"`.
- Nomi ricetta unici con confronto `fold_name` (minuscole, senza accenti, spazi collassati); possono coincidere con nomi di alimenti.
- `save_profile` con riferimento a ricetta inesistente → errore `invalid_format`; `recipe_qty` salvato senza voci di ricette/ingredienti inesistenti.
- Eliminare ricetta in uso (week o exceptions di qualsiasi profilo) → errore `in_use` con messaggio `"Ricetta usata da: <nomi profili separati da ', '>"`.
- Nuovi codici errore websocket: `in_use`, `duplicate_name` (messaggio `"Esiste già una ricetta con questo nome"`); esistenti: `conflict`, `not_found`, `invalid_format`.
- UI italiana, nessuna dipendenza nuova, pannello in un solo file, comandi senza `require_admin`.
- Test: `MSYS_NO_PATHCONV=1 docker run --rm -v "D:/code/ha-shared-diet:/app" shared-diet-test python -m pytest tests/ -q`; JS: `MSYS_NO_PATHCONV=1 docker run --rm -v "D:/code/ha-shared-diet:/app" -w /app node:22-slim sh -c "node --check custom_components/shared_diet/frontend/shared-diet-panel.js && for f in tests/js/*.test.mjs; do node \$f || exit 1; done"`.
- Versione finale `0.2.0` (const `VERSION` e `manifest.json`).

## Review Focus

1. Dati salvati prima di questa versione (niente `recipes`, profili senza `recipe_qty`) → si caricano e funzionano senza errori (test in Task 2).
2. Ricetta rinominata/ingrediente aggiunto o rimosso dopo che una persona ha personalizzato le grammature → spesa e sensori usano default per i nuovi, ignorano i rimossi (test in Task 1).
3. Due utenti: uno elimina una ricetta mentre l'altro salva una dieta che la usa → nessun crash; il salvataggio successivo viene rifiutato o la ricetta appare "Ricetta mancante" e non entra nella spesa (test in Task 1 e Task 2).
4. Ricetta come alternativa OPPURE scelta nella scheda Scelte → spesa usa gli ingredienti solo se scelta (test in Task 1).
5. Nome ricetta duplicato con maiuscole/accenti diversi ("Caffè latte" / "caffe latte") → rifiutato (test in Task 2).

### Task 1: Espansione ricette in `model.py`

- `expand_item(item: dict, profile: dict, recipes: dict) -> dict` - item semplice: restituito invariato; item-ricetta: `{"recipe": rid, "food": name, "note": recipe_note, "ingredients": [{"food","qty","unit","note": ""}], "missing": False}`; ricetta inesistente: `{"recipe": rid, "food": "Ricetta mancante", "note": "", "ingredients": [], "missing": True}`.

- `shopping_items(profiles, start, end, recipes: dict | None = None) -> list[str]` - item-ricetta contribuiscono i loro `ingredients` (grammatura effettiva), con le stesse regole di normalizzazione/somma; ricetta mancante non contribuisce.
- `format_item(item) -> str` - item-ricetta: `"<food>: " + ", ".join(format_item(i) for i in ingredients)`; mancante o senza ingredienti: solo `food`.

### Task 2: Ricettario in `store.py`

**Files:** Modify `custom_components/shared_diet/store.py`; Test `tests/test_store_recipes.py` (nuovo).

**Interfaces - Consumes:** `fold_name` (Task 1). **Produces** (metodi di `DietStore`, copie profonde come ora, listener chiamati dopo ogni modifica):
- `recipes -> dict[str, dict]`
- `async_create_recipe(name: str) -> dict` (`id` uuid hex, `note ""`, `ingredients []`, `rev 1`; nome duplicato → `DuplicateNameError`)
- `async_save_recipe(recipe: dict) -> dict` (id sconosciuto `KeyError`; rev vecchio `ConflictError`; nome duplicato di un'altra ricetta → `DuplicateNameError`)
- `async_delete_recipe(recipe_id: str) -> None` (in uso → `InUseError(profile_names: list[str])`, `str(err)` = `"Ricetta usata da: A, B"`; id sconosciuto no-op)

- Caricamento: dati senza `recipes` → `{}`; profili senza `recipe_qty` → `{}`. `_new_profile` include `recipe_qty: {}`.
- Eccezioni nuove in `store.py`: `DuplicateNameError(Exception)`, `InUseError(Exception)` con attributo `profile_names`.
